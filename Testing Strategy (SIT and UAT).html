Scope of Services — 4. Testing Strategy (SIT and UAT)

Testing Strategy (SIT and UAT)

Macquires will verify the Syriatel CRM in two controlled phases before production cutover. System Integration Testing (SIT) proves that the application correctly calls Syriatel’s core telecom interfaces (billing, network, SMS, payments) and handles failure modes. User Acceptance Testing (UAT) proves that business users can complete showroom and back-office journeys on realistic data with the correct roles and environments.

Macquires will provide test plans, automated regression suites, integration observability built into the product, and clear entry/exit criteria for each phase. Syriatel participation is required for sandbox connectivity, test MSISDNs, and business sign-off scripts.

SIT architecture

RFP — external systems & API validation approach

Macquires will integrate the CRM with the external Syriatel core telecom systems listed below. Each integration is implemented behind a typed .NET contract in the application layer; the infrastructure layer supplies either a live connector (SIT/UAT when enabled) or a logged fallback path when the interface is disabled for resilience testing.

During SIT, Macquires validates APIs end-to-end: request/response correlation, idempotent replay, retry and circuit-breaker behaviour, and persistence of every attempt in integration logs for audit.

Technical approach — validating APIs during SIT

Macquires will execute a layered SIT strategy that combines automated tests, operator-visible logs, and scripted interface scenarios. The goal is to prove that every confirm/provision path writes the correct downstream message and leaves a traceable correlation ID in the CRM.

Layer 1 — Automated regression (CI / pre-UAT)

Macquires will run the existing Application.Tests and Domain.Tests suites (telecom eligibility, SIM swap, termination workflow, payment velocity, bulk import headers, integration circuit-breaker contracts, dashboard widgets, RBAC). These tests validate business rules and integration result contracts before any Syriatel sandbox is available.

  • Eligibility and workflow: selling line, SIM swap, takeover, change number, suspension/reconnect, termination, refunds, device sale, offer migration.
  • Integration resilience: IntegrationCircuitBreakerTests — fallback still allows workflow continuation with QueuedForSync / PendingExternal.
  • HLR operation naming and termination provisioning contracts.

Layer 2 — Live interface SIT (Syriatel sandboxes)

For each external system, Macquires will execute interface test packs mapped to CRM operations: activation (CBS + HLR CreateSubscriber), SIM swap, suspend/reconnect, termination, recharge confirm, refund to wallet, VAS activate/deactivate. Each test case records: operation number, correlation ID, success/failure, latency, and raw payload reference in logs.

SIT entry and exit criteria

SIT entry: SIT environment deployed; sandbox URLs and credentials configured; test MSISDN/SIM/ICCID ranges allocated; integration toggles set to live for systems under test.

SIT exit: All mandatory interface packs pass; zero open Sev-1 integration defects; billing and HLR logs show successful provision for golden-path scenarios; fallback/recovery scenarios documented; Macquires and Syriatel integration owners sign the SIT completion record.

UAT prerequisites

RFP — environments, seeding, roles, and workstations before business testing

Before Syriatel business users begin UAT, Macquires and Syriatel will jointly verify the prerequisites below. UAT uses a dedicated environment isolated from production, populated with representative subscriber data (migration rehearsal or controlled seed), and accounts that mirror real showroom, back-office, call-center, and management personas.

Macquires will prepare UAT scripts per journey (activation, SIM swap, payment/recharge, refund, suspension, Customer 360 search). Syriatel will assign named testers per role and record pass/fail against acceptance criteria.

Each environment requires: SQL Server database (schema aligned via EF migrations + telecom SQL runbook), ASP.NET Core API host, static front-end assets, HTTPS certificate, and configured appsettings for connection strings, field encryption keys, and bulk-import storage. UAT must not share a database with SIT.

Database seeding and test data

Macquires will load UAT data using one of two approved approaches (selected in the migration workshop):

  1. Migration rehearsal data — Subset or full wave from bulk import (customers, MSISDN/SIM, package migration) representing real Syriatel formats (preferred for business realism).
  2. Controlled demo seed — System seeders: roles, permissions, global settings, product catalog, TelecomSyriatelSeeder subscribers, Customer 360 enrichment, sample technical tickets (for empty UAT only).

Regardless of source, UAT data must include: active and suspended lines, at least one corporate and one individual customer, prepaid and postpaid subscription types, available MSISDN/SIM inventory, product offerings for migration tests, and non-production payment references. National IDs in UAT must be fictional or anonymized per Syriatel privacy rules.

Client workstations and access

Syriatel must provide UAT workstations that meet the following minimum standard. Macquires will publish a short UAT workstation checklist before testing starts.

  • Browser: Current Microsoft Edge or Google Chrome; JavaScript enabled; pop-ups allowed for document download where needed.
  • Network: HTTPS access to UAT CRM URL; VPN or private link if the environment is not public internet.
  • Resolution: 1366×768 or higher (Telecom Hub and Back Office Dashboard are responsive but optimized for desktop).
  • Authentication: Each tester receives individual credentials (JWT session); shared accounts are not permitted for sign-off.
  • Locale: Arabic RTL UI validated; English where dual-language labels apply.
  • Peripherals (showroom UAT): If document scan upload is tested, workstation file picker and PDF/image upload for identity documents on takeover/lost-SIM flows.

UAT exit criteria

UAT is complete when Syriatel business owners sign acceptance for all in-scope journeys, open defects are either fixed or formally waived with expiry date, and a go-live readiness note confirms migration data strategy for production. Macquires will not request production cutover until written UAT sign-off is received.

Scope note: Demo builds ship with mock payment, charging, SMS, and directory connectors; SIT proves adapter contracts and logs. UAT may run on mocks for business process sign-off while parallel SIT completes live sandbox certification—schedule agreed in the test plan.

Summary

SIT: Macquires lists nine external telecom integration domains (CBS billing, HLR, SMS, charging, payment gateway, directory, VAS, device logistics, eSIM), validates them through automated tests, sandbox interface packs, and built-in billing/integration logs with health toggles and resilience patterns.

UAT: Syriatel receives isolated UAT environment, seeded or migrated test data, five telecom personas with correct RBAC, verified workstations and VPN/HTTPS access, and a joint checklist before business testers execute signed scripts.

Macquires commits to deliver SIT/UAT test plans, support defect triage during both phases, and gate production on SIT completion and written UAT acceptance.
